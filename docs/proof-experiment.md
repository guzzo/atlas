# Hidden-limit proof experiment

The experiment uses Bulletproofs 5.0.0 over Ristretto255. Its sole private policy predicate is `public_amount <= private_limit`. The limit's range is 32 bits; the public amount is also constrained to 32 bits by the outer protocol. The policy structure is public.

## Authenticated statement

Let `G` and `H` be `PedersenGens::default()` from the pinned Bulletproofs library, and let `r` be a uniformly random scalar generated by the library's cryptographic RNG. Acme publishes the commitment:

```text
C = limit * G + r * H
```

Acme signs a policy document containing `C`, version, predecessor, predicate identifier, units and validity interval. It delegates a policy-signing key, which signs the complete request-bound capability. Globex verifies both signatures and resolves active state before checking the proof. The range proof itself does not verify Ed25519 signatures; authentication is the surrounding verified composition.

For public amount `a`, the prover creates one aggregated 32-bit range proof for:

```text
values      = [limit, limit - a]
blindings   = [r, r]
commitments = [C, C - a * G]
```

Proving both ranges fixes the interpretation of the limit as a 32-bit nonnegative integer and avoids a modular-underflow interpretation of subtraction. The verifier computes the second commitment itself; the prover cannot supply an easier commitment. Using the same blinding here exposes only the already public difference `a`.

The Merlin transcript starts with `passport.hidden-limit.v1` and appends, in order:

| Label               | Bytes                                                        |
| ------------------- | ------------------------------------------------------------ |
| `program`           | UTF-8 `passport.hidden-limit.bp5.ristretto.32x2.v1`          |
| `commitment`        | 32 decoded compressed-point bytes                            |
| `amount`            | Public unsigned amount as four little-endian bytes           |
| `capability_digest` | 32 decoded SHA-256 bytes of the canonical capability payload |

That capability authenticates agent, runtime, issuer, audience, recipient, resource, action, units, nonce, policy version/commitment, expiry and request digest. Consequently proofs cannot move between requests, policies or capabilities. The verifier pins this complete profile and library implementation; it does not accept a prover-selected program. Changing this construction requires a new program identifier and conformance vectors.

## Privacy and limits

- Fresh randomness prevents dictionary testing of the commitment even for a small numeric limit. The same limit produces different commitments.
- The verifier learns the amount and inequality result; it can infer that the limit is at least the largest allowed amount. It does not learn the blinding or exact limit from the proof transcript.
- Repeated chosen-amount authorization queries can reveal a threshold. Preventing that policy oracle is outside this proof and needs a product/adversary decision.
- The fixtures use development identities. Bootstrap chooses the initial private limit randomly, stores it only in Acme's local configuration, and does not print it.
- This does not hide the policy program, prove general Cedar semantics, attest source truth, prove runtime integrity, or account for cumulative spending.
- A proof timestamp cannot establish live revocation. Signed live-state resolution and final expiry checks remain mandatory.
- Independent cryptographic review and adversarial audit are still required. The experiment uses established libraries but the protocol composition is new.

The Cedar adapter uses the explicit policy in `workers/policy-proof/policy.cedar`, validated against `schema.json`. Its private context includes the same limit. Tests compare the full purchase decision at integer boundaries, actually generate/verify passing proofs, reject over-limit witnesses, and reject changed public amount/context/commitment.

## Benchmark

Run `./bin/passport benchmark` with the stack running and `ENABLE_ZK=1`. It measures ten samples after one warmup and saves `.local/reports/benchmark.json`. Only public measurements are printed; the witness is never written to the report.

The initial local measurement on an AMD Ryzen 9 9950X3D, Rust release builds in Docker, including HTTP round trips:

| Measurement         |                           Result |
| ------------------- | -------------------------------: |
| Proof size          | 672 bytes (1,344 hex characters) |
| Median generation   |                          7.68 ms |
| p95 generation      |                          8.72 ms |
| Median verification |                          2.93 ms |
| p95 verification    |                          3.50 ms |

These are single-machine observations, not capacity or production SLO claims. The current synchronous experiment is comfortably within the 60-second capability lifetime on this machine. It needs load, constrained-CPU, concurrent proving and denial-of-service benchmarks before choosing a deployment budget. Disable the path with `ENABLE_ZK=0`; baseline signed authorization remains available.

Implementation references: [Bulletproofs API](https://docs.rs/bulletproofs/5.0.0/bulletproofs/struct.RangeProof.html), [Cedar authorization](https://docs.cedarpolicy.com/auth/authorization.html), and the dependency versions pinned in `Cargo.lock`.
